## What is TOON?

**TOON (Token-Optimized Output Notation)** is a compact, LLM-friendly
serialization format for MCP tool results. It replaces JSON's structural
overhead (braces, colons, redundant quotes) with a flat `key=value|…`
notation, using dot-notation for nesting and a minimal MCP envelope.

### Format comparison (echo tool, small payload)

```
# Full MCP JSON-RPC envelope (106 chars, 29 tokens):
{"jsonrpc":"2.0","id":1,"result":{"content":[{"type":"text","text":"{\"echo\":\"hello\",\"length\":5}"}]}}

# MCP TOON envelope (24 chars, 8 tokens):
[r:1]echo=hello|length=5

# Bare JSON (27 chars, 9 tokens):
{"echo":"hello","length":5}

# Bare TOON (19 chars, 5 tokens):
echo=hello|length=5
```

## Interpretation

Across 11 benchmark scenarios, MCP TOON envelopes consume on
average **50.9% fewer tokens** than canonical MCP JSON-RPC envelopes.

The savings are most pronounced for:
- **Payloads with many small fields** — JSON key overhead dominates.
- **Nested structures** — dot-notation eliminates multiple layers of braces.
- **Repeated key patterns** (e.g., agent observation logs) — key names are
  repeated per entry in JSON but amortised in TOON.

The savings are smallest for:
- **Large string values** — the string content itself dominates token count
  in both formats, so structural savings are diluted.

### When does this matter?

| Context | Impact |
|---------|--------|
| Multi-step agent loops (many tool calls per turn) | High — saves accumulate each step |
| Long context windows with many tool results | High — pushes less content into the window |
| Cost-sensitive deployments (token-priced APIs) | Direct cost reduction |
| Single tool call per turn | Low — absolute saving is small |
